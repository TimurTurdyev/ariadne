# Changelog

All notable changes to this package are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.2.0] - 2026-02-28

- **Breaking: the package is renamed to `timurturdyev/ariadne`.** The namespace is `TimurTurdyev\Ariadne`, the provider `AriadneServiceProvider`, the config file `config/ariadne.php` under the key `ariadne`, the publish tag `ariadne-config`. Screen cache keys start with `ariadne:screen:`, the locks of Manticore rebuilds with `ariadne.rebuild.`, and the live tests read `ARIADNE_MANTICORE` and create tables named `ariadne_it_*`. In the console the provider stops with a `RuntimeException` while `config/simple-search.php` exists and `config/ariadne.php` does not: the old file would be ignored, and the package would quietly run on its defaults. The steps are in [UPGRADE.md](UPGRADE.md).
- **The screen cache works on Laravel 13.** A fresh Laravel 13 application sets `cache.serializable_classes` to `false`, the stored `SearchResult` came back as `__PHP_Incomplete_Class`, and the second request of a screen ended in a `TypeError`. `SearchCatalog` now stores a `serialize()` string and reads it back with the classes of the package alone, whatever the store allows; an entry that does not read back is a miss, and the screen is built anew. The stored form changed, so the keys moved to `v2`: the screen cache cools once after the upgrade. With a cache, the attributes, payload and extra of a `Hit` must hold arrays and scalars only.
- **`screen.palette_on_price`, off by default.** With `keep_zeros`, a screen narrowed by a price alone gets a palette too, so the values the price zeroes are dimmed instead of hidden. It costs one more count, which made such a screen 1.5 to 2.3 times slower on the flat table, hence off. `SearchCatalog` and `QueryPlan::forQuery()` take it as `paletteOnPrice`, `DisjunctivePolicy::keepsZeros()` tells whether zeros are kept, and `QueryPlan::paletteKey()` now follows the planned intents.
- **README** rewritten: the SQL path on the flat table first, then your own engine behind `CatalogIndex`, imports in every snippet and the traps in one box. The flat table is indexed on `(facet, value, item_id)` and has no foreign key, so the rows of a deleted document are removed by the code that deletes it. The controller makes models from the hit rows with `Model::hydrate()` instead of a second query.

Version 0.1.0 was published as `timurturdyev/simple-search`.

## [0.1.0] - 2026-02-21

First version. The core of a faceted catalog without a domain: `Query` over a `Scope` of field constraints, a `QueryPlan` of intents (main, price bounds, palette, what-if), the disjunctive panel of `DisjunctivePolicy` with `keepZeros` and `minValues`, `QueryStringCodec` in the `comma` and `brackets` address styles, `PanelLinks` with ready addresses and landing pages through `LinkBase::landing()`, and `SearchCatalog`, which builds one screen and caches it when given a cache. Two ports, `CatalogIndex` and `FacetDictionary`, with a SQL implementation over a flat facet table: `SqlCatalogIndex`, `SqlCatalog`, `FlatFacetDictionary`. For Manticore: `Connection` with a handshake probe, `Table` as a schema in data with `drift()`, a batch `Writer`, and two publications that rebuild tables without downtime, `SwapCopies` and `AttachShadow`. `Text\Layout` reads text typed in the latin keyboard layout as cyrillic. The service provider binds the classes only when the application has not, and publishes the config under the `simple-search-config` tag.

Behaviour settled before the release:

- Addresses. `QueryStringCodec::MAX_AMOUNT` (1e12 address units): a price bound above it, infinite or not a number reads as absent, a fractional one is rounded to two decimals, a reversed range is swapped. `canonical()` drops facet values that cannot be a slug and is idempotent. `isReserved()` takes a facet slug and checks the parameter name the style writes; an all-digit slug is reserved. The search text is trimmed as the TrimStrings middleware does and again after the cut to 128 characters, so an address reads back the same.
- Panel links. `LinkBase::only()` keeps the named foreign parameters, `LinkBase::MAX_FOREIGN_LENGTH` caps the foreign part of every link at 1024 encoded bytes. Paths are normalized to one leading slash, a landing page without a pinned choice falls back to the main path, and there is no `next` link on page `PageRequest::MAX_PAGE`.
- Screen cache. `Query::signature()` puts the prefix mark before the encoded text and keeps the operator as stored; `PriceScale::signature()` writes the exact rate. `FacetPanel` always holds a list. A refresh that meets an engine outage keeps the stale screen for another 300 seconds and logs a warning instead of reporting an error.
- SQL. `SqlCatalog` requires `id` and `price`. The id is appended as the last sort key, conditions of a field closure are wrapped in brackets, price bounds go into SQL as numeric literals, so a price expression compares as a number.
- Manticore. Both publications refuse a switch when an empty table of the set would replace a filled one or when `lockSeconds` passed since the lock was taken (`PublishRefused` has an optional reason). `PublishFailed` carries `table` and `switched`. `AttachShadow` flushes every shadow first and alters only the mutable settings that differ. `Table::drift()` reports `unexpected setting`, compares types case-insensitively and sizes in bytes; setting values are escaped. `Connection` has a read timeout of its own (`read_timeout`, 30 seconds) that leaves the other connections of the process alone; a response that does not come in time is a `CatalogIndexUnavailable` without a retry. It reconnects after a dropped link and retries a request that did not reach the engine once, binds int and bool as numbers, reads an empty timeout as 5 seconds and connects `localhost` over TCP. `Writer::literal()` rejects NAN and INF and strips NUL bytes.
- Requires `ext-ctype`.
